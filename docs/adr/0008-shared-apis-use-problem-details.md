# Shared APIs use RFC 9457 Problem Details

New Shared Wheel APIs return `application/problem+json` responses using RFC 9457 fields, stable problem-type URIs, and narrowly scoped extensions such as `currentVersion` or field-level validation errors. Malformed requests and all input or domain-validation failures are `400 Bad Request`; missing wheels or Spin records are `404 Not Found`; stale expected versions are `409 Conflict`; and unexpected failures are `500 Internal Server Error` without exception, SQL, or stack details. The MVP does not distinguish `422 Unprocessable Content`, because its browser would handle that response exactly like other invalid input. Spring MVC's `ProblemDetail` and a global controller advice provide the mapping while preventing persistence exceptions and stack details from leaking to clients. The original `POST /api/spins` deliberately retains its documented `{ "message": "..." }` error body for backward compatibility; the two formats are a legacy boundary rather than a template for future inconsistency.
