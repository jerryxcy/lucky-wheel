# PostgreSQL is optional Shared Wheel infrastructure

The application remains one runnable jar whose default configuration provides the original Local Wheel without a DataSource, migrations, Docker, or other setup. Shared Wheel persistence is enabled explicitly; once enabled, PostgreSQL configuration and successful migrations are required and startup fails rather than silently falling back to local-only behavior. Shared development uses PostgreSQL from Docker Compose, and database integration tests use disposable PostgreSQL instances from Testcontainers rather than H2, so transaction, locking, constraint, and migration behavior is tested against the production engine. Flyway SQL migrations are the sole source of schema changes in every environment, while Hibernate uses `ddl-auto=validate` rather than creating or updating the schema. ADR-0001 continues to govern Local Wheels, while its stated shared-roster trigger is now handled by this optional PostgreSQL capability.
